# v0.15 stakeholder-readiness audit

This milestone is a targeted software-consistency and usability review before initial external stakeholder testing. It is **not** a formal health-economic model validation certificate and does not assess the scientific quality of user-supplied evidence.

## What was reviewed

### Navigation and product structure

- `app.py` registers every stakeholder-facing workspace.
- Automated tests verify that every literal `st.Page(...)` and `st.page_link(...)` target resolves to an existing page file.
- Home now represents the full platform: clinical modelling, value for money, Population & Uptake, BIA, clinical linkage, resource/capacity planning, policy interpretation, transparency and reproducibility.

### Population formulas

Direct projection:

`population_year_t = population_year_1 × (1 + annual_growth)^(t-1)`

Covered lives use an independent growth rate in direct mode.

Top-down funnel:

`eligible = covered/catchment × prevalence × diagnosed/identified × clinically eligible × access/coverage`

Formula-derived values remain live. Manual annual values are an explicit override and are never silently replaced by later formula changes.

### Population & Uptake allocation

For each scenario/year/option:

`allocated_people = eligible_population × option_share`

Current and future shares are each required to sum to 1. The platform does not silently normalise invalid shares.

If the shared scenario becomes invalid, its exported population/mix rows are removed so a downstream capacity analysis cannot reuse a previous valid scenario without the user noticing.

### Budget Impact Analysis

For each scenario/year/option:

`treated_people = eligible_population × treatment_share`

`option_cost = treated_people × sum(included per-treated-person cost components)`

Annual net budget impact:

`future scenario expenditure - current scenario expenditure`

Cumulative budget impact is the running sum of annual net impact.

When covered lives are supplied:

`PMPM = annual net budget impact / (covered_lives × 12)`

Annual cost change is compounded from the Year-1 unit cost. BIA v0.15 uses the same reactive/manual population distinction as the shared Population & Uptake page.

A validated BIA now publishes canonical population and treatment-mix rows for downstream use. If the current BIA becomes invalid, those validated exports are withdrawn. Policy Interpretation consumes the canonical validated BIA contract; clinical linkage and capacity are guarded from entering with an invalid BIA state while legacy widget-key consumers are kept synchronised from the canonical validated export.

### Resource & Capacity Planning

Annual cross-sectional demand:

`required_units = treated_people × resource_units_per_person`

For new treatment starts, year-since-initiation resource profiles are stacked across initiation cohorts into each budget year.

Residual available capacity:

`available_capacity = total_capacity - capacity_committed_to_other_uses`

`shortfall = max(required_units - available_capacity, 0)`

`headroom = max(available_capacity - required_units, 0)`

Demand and capacity must use the same natural unit. No silent conversion is performed between beds and bed-days, cylinders and litres, vehicles and vehicle-hours, or analogous resource measures.

### Clinical resource linkage

Decision-tree resource events are weighted by the probability of reaching the mapped node/event and assigned to an annual bucket using explicit model time.

Markov and semi-Markov resource rewards are projected using model occupancy and the selected cycle length. Per-year resource rewards are scaled by cycle length; per-cycle rewards are not. Annual aggregation requires the clinical cycle length to divide one year exactly.

Longitudinal linked resource profiles require annual new treatment starts. A cross-sectional prevalence stock does not identify time since treatment and is not silently treated as incident cohorts.

### State-transition CEA consistency

The existing v0.13 regression suite checks that base case, DSA and PSA use the same compiled model settings, including non-annual cycle length. Parameter-linked initial response/cure fractions and utility overrides are covered by sensitivity regressions. Stored PSA results use model/settings fingerprints and are invalidated when substantive settings change.

Advanced Markov probability-to-rate conversion remains explicit when disease progression probabilities must compete with rate-based background mortality. No automatic unlabelled conversion is performed.

### Persistence and restoration

State-transition load/restore re-applies active cycle length, horizon, accrual timing, discounting and threshold settings, recompiles the model, and invalidates stochastic results when the restored model/settings fingerprint differs.

### Policy interpretation

Value, affordability and feasibility remain separate domains. Affordability now requires the current validated BIA handoff. Feasibility uses the most recently validated capacity result, whose upstream fingerprint is checked before any page can consume it.

## New stakeholder-readiness tests

- numerical Population & Uptake → BIA → Capacity integration regression;
- canonical BIA-session handoff and stale-state rejection tests;
- navigation/page-link integrity tests;
- compilation now includes `ui/*.py` in addition to `app.py`, `pages/*.py` and `model/*.py`;
- CI boots the Streamlit server and polls `/_stcore/health` before declaring the build healthy.

## Important boundaries for stakeholder review

1. **Software consistency is not scientific validity.** The platform cannot determine whether an evidence source is unbiased, whether a structural assumption is scientifically appropriate, or whether results transfer to a particular jurisdiction.
2. **Population → BIA is a snapshot.** It is intentionally editable after copying and is not a hidden live two-way synchronisation.
3. **Prevalent-stock longitudinal linkage is not inferred.** It would require explicit information about time since treatment/state occupancy.
4. **Capacity planning is not operations-research scheduling.** It reports demand, utilisation, headroom and shortfall; it does not optimise queues or ration patients automatically.
5. **BIA/capacity uncertainty is less mature than CEA uncertainty.** Richer scenario and probabilistic management remains a planned extension.
6. **No persistent account/database layer exists yet.** Session state is in-memory; state-transition file persistence is the current reproducible model-storage mechanism.
7. **Policy Interpretation is a communication layer, not a recommendation engine.** It reports what the validated analyses imply under the stated assumptions without issuing an adopt/reject instruction.

## Suggested initial stakeholder testing

Reviewers should deliberately test both ordinary and failure pathways:

- change population growth/funnel inputs and confirm annual projections update immediately;
- copy a shared population snapshot to BIA, change BIA values, and confirm the shared source is unaffected;
- make treatment shares invalid and confirm downstream reuse is blocked;
- change BIA population inputs and confirm affordability interpretation follows the new validated result;
- use capacity with staff-hours, bed-days and at least one consumable/supply resource;
- change an upstream population/clinical input after running capacity and confirm the previous feasibility result is invalidated;
- save/load a state-transition model with non-default cycle/horizon/threshold settings and confirm the restored analysis uses those settings;
- test a non-annual Markov cycle and confirm base case, DSA and PSA remain aligned;
- inspect the Transparency Check and confirm that complete documentation is not presented as proof of scientific quality.
