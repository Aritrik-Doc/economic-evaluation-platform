# v0.13 validity and stability patch

This release focuses on analytical validity and reproducibility in the Cohort Markov and Advanced Markov workflows. It is intentionally a corrective release rather than a new modelling family.

## Confirmed defects corrected

### Active settings and persistence

State-transition Save / Load / Audit previously exposed a second settings form with independent defaults. That could save or restore a model structure alongside cycle length, horizon, threshold or discount settings that differed from the active modeller. v0.13 removes that duplicate settings source. The saved bundle now takes its methods and engine settings from the active Cohort Markov or Advanced Markov workspace, and restore writes those settings back into the modeller controls.

Restoring a different model also invalidates stored PSA results from the previous model/settings state.

### Parameter-linked starting cohorts

Starting-state allocation was previously numeric only. This meant a parameter such as cure probability or SVR could exist in the parameter library without affecting DSA or PSA when the post-treatment cohort split had been typed separately as fixed proportions.

Starting allocation may now be:

- fixed;
- the value of a probability parameter; or
- one minus a probability parameter.

For a binary post-treatment split, a typical pattern is `Cured = p_cure` and `Uncured = 1 - p_cure`. Parameter overrides and PSA draws then propagate into the starting cohort. The engine still requires the resolved distribution to sum to one and does not silently normalise invalid draws.

### Cohort trace display

The Cohort Markov page now labels trace columns with their state IDs and adds explicit cycle/time columns before plotting. The previous page constructed an unlabeled numeric DataFrame and then searched for a `cycle` column that did not exist.

### CEAC display range

Cohort and Advanced Markov CEACs no longer stop automatically at twice the selected decision threshold. Users specify the minimum threshold, maximum threshold and grid resolution. The selected decision threshold remains the value used for pairwise probability cost-effectiveness and NMB/INMB calculations.

## Explicit probability-to-rate conversion for background mortality

Automatic age-specific background mortality continues to be combined only within a coherent rate-based competing-risk row. This is a methodological safeguard, not a defect.

v0.13 adds a third transition representation to Advanced Markov:

- `probability` — an interval probability for the model cycle;
- `rate` — a cause-specific continuous rate/hazard per year;
- `probability_to_rate` — an interval probability that the modeller explicitly elects to convert to a constant cause-specific rate.

The last form requires the source probability interval. The conversion assumes a constant cause-specific hazard over that source interval. Once converted, it may be combined jointly with other rates and automatic background mortality through the competing-rate calculation.

A plain probability row is still rejected when automatic background mortality must be added. The platform does not silently impose a constant-hazard interpretation on an interval probability.

## Transition import compatibility

The Advanced Markov compiler now accepts the standard cohort alias `probability_parameter_id` when an advanced `parameter_id` is not present. A residual self-transition from a standard Markov model is omitted because the semi-Markov engine derives staying in the origin state internally. A residual transition to a different state remains an error because translating it would require an unstated modelling assumption.

## Sensitivity and PSA consistency

The Markov analysis pages now display the exact cycle length, horizon/max cycles, accrual timing, discount rates and decision threshold used by the current compiled analysis.

Before a deterministic sensitivity result is displayed, the page checks that the sensitivity engine's base INMB matches the INMB calculated from the displayed base-case strategy results. If those values diverge, sensitivity output is withheld rather than shown as valid.

PSA remains tied to a model/settings fingerprint. Editing the substantive model or analysis settings makes an earlier stored PSA result stale.

Regression tests now include a six-month-cycle model in which both a cure parameter linked to the starting cohort and a utility parameter must change DSA results, and the cure distribution must propagate through PSA outcomes.

## Advanced Markov deterministic sensitivity

The existing pure semi-Markov sensitivity functions are now exposed in the Advanced Markov page as:

- tornado analysis;
- one-way INMB analysis;
- two-way INMB decision map; and
- threshold/switching analysis.

These analyses all rerun the same compiled model under the same settings as the base case.

## Remaining methodological boundaries

- A probability-to-rate conversion is only as credible as its constant-hazard assumption and source interval.
- Multi-category parameter-linked starting distributions must be coherently constrained; the platform does not silently renormalise them.
- A standard cohort Markov model continues to treat transition probabilities as probabilities for its selected cycle and does not silently rescale them when cycle length changes.
- A content hash detects file changes but is not a digital signature or proof of authorship.
